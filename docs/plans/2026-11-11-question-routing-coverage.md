## 문제와 범위

배포된 PR #27에서도 `AIS 관련 정보를 알려줘`는 현황 경로에 들어가지 않는다. `MRV 관련 데이터 있어?`에는 DB 현황 경로 자체가 없다. 기존 제한형 모델 계획도 규칙이 허용한 작업만 선택해 낯선 표현에 대한 우회 효과가 작다.

기존 조회·계산·문서·항만 기능을 재사용하고, 자료 현황 조회와 제한된 의미 분류를 연결한다. 모델은 작업 종류만 선택하며 SQL·숫자·식별자·날짜·권한을 결정하지 않는다. 불명확하거나 지원하지 않는 의도는 되묻는다. 운영 배포 및 모델 자체의 범용 정답률 개선은 범위 밖이다.

## 실제 모델 시험과 범위

이미 설치된 **Qwen2.5 3B / Ollama / 노트북 CPU**만 사용했으며 새 모델을 내려받지 않았다. 공개 용어집의 짧은 정의 발췌 하나, `json_schema`, 60초, 출력 최대 384토큰, thinking 옵션 미전송으로 시험했다. 모델 최초 적재는 **16.875초**, “조종불능선에 대해 설명해줘”는 **25.563초**에 원문과 맞는 정의·정확한 인용을 반환했다. 같은 발췌에 없는 선장 이름 질문은 **4.500초**에 근거 부족을 반환했다. 짧은 근거 두 사례이며 운영 검색 전체·모델 품질 정답률을 통과한 결과가 아니다.

초기 3필드·긴 분류 지시는 6초 시간 초과/검증 실패/모호한 판단이 나왔다. 단일 action·32토큰·12초와 짧은 예시로 줄인 실제 분류 5건은 **3건이 기대 작업과 일치, 2건은 되묻기**였다. 분류 시간은 1.312–11.094초다. 따라서 범용 의미 분류 정확도를 보증하지 않는다. 이 두 유형의 흔한 자료 현황/절차 표현은 기존 규칙 경로에서도 보완했으며, 형식·인증·잘못된 의도 처리의 모의 회귀 결과와 실제 모델 분류 수치를 구분한다. 운영 모델 환경의 추가 평가는 필요하다.
