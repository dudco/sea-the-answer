# 역할1·2·3 연동 안내

역할4는 정형 데이터와 조회·계산 서비스를 제공합니다. 팀 구성원의 세부 역할을 임의로 가정하지 않고, UI·Agent·백엔드에서 공통으로 필요한 계약을 정리했습니다. 기존 앱의 자동 연결이나 팀 인터페이스 합의 완료를 의미하지 않습니다.

## 권장 연결 흐름

```text
사용자 화면 / Agent
  → 팀 백엔드에서 사용자·선박 접근 권한 검사
  → 역할4 API 호출 (서버가 Bearer 토큰 보관)
  → 출처·단위·품질·경고와 함께 결과 표시
```

역할4 토큰 하나는 역할4 데이터 전체 조회 권한을 가집니다. 사용자별 권한 검사와 감사 저장은 팀 백엔드에서 구현해야 합니다. 기본 API 주소는 `http://127.0.0.1:8000`이며 배포 시 팀 서버 설정으로 주입합니다. PostgreSQL 접속 정보와 토큰은 프런트엔드에 전달하지 않습니다.

## 호출 계약

| 목적 | 요청 | 응답 처리 |
|---|---|---|
| 실제 MRV 조회 | `POST /api/role4/query`, `dataset=real_annual`, `year_start/year_end` | 연간·보고기간 자료, 일별 분해 금지 |
| 합성 Noon 조회 | 같은 API, `dataset=synthetic_noon`, `start/end`, 선택적 선박·항차 | 실제 운항과 구분하여 개발용 표시 |
| 계산 계수 | `GET /api/role4/factors` | 버전·근거·단위 보존 |
| CO₂·기간 지표 | `POST /api/role4/calculate`, `scope`, 명시적 `fuel_mappings` | `status`, `blockers`, `intensity_blockers` 확인 |
| 조회 도우미 | `POST /api/role4/ask`, `question`, `scope` | 질문에서 필터를 추출하지 않음; 선택된 scope 유지 |

전체 입력·응답은 [조회 계약](docs/role4/QUERY_TOOL.md), [계산 계약](docs/role4/CALCULATION_TOOL.md), 실행 중인 `/docs`에서 확인합니다. 임의 SQL을 받지 않으며 모델이 SQL이나 필터를 변경하도록 연결하지 않습니다.

## 통합 시 반드시 맞출 항목

- **선박 ID:** 실제는 `REAL:IMO:1234567`, 합성은 `SYN:SIM-BULK-01` 형식입니다. 기존 앱의 `HAE-01` 같은 ID와 동일하다고 가정하지 말고 명시적인 매핑과 권한 검사를 둡니다.
- **정밀도:** numeric은 십진 문자열입니다. UI 표시 형식과 계산 입력을 분리하고 클라이언트에서 재계산하지 않습니다. 결측 null을 0으로 바꾸지 않습니다.
- **페이지:** `total`은 전체 건수, `rows`는 현재 페이지입니다. `next_offset`으로 이동하며 첫 페이지를 전체 기간 합계로 사용하지 않습니다.
- **계산 제한:** HTTP 200이어도 `status=blocked`일 수 있습니다. 공식 CII와 등급은 null이며 임의 등급을 생성하지 않습니다. 실제 MRV 보고 CO₂와 재계산 CO₂는 별도 필드입니다.
- **오류:** 401 토큰 누락, 403 토큰 오류, 422 입력 계약 위반, 503 DB·스키마·조회 오류입니다. 사용자에게 복구 가능한 안내를 표시합니다.
- **출처:** `source_id`, 원본 행·체크섬, `provenance_json`, 단위·경고를 제거하지 말고 근거 확인에 사용합니다.

## DB와 운영

역할4 스키마는 기존 앱 테이블과 분리됩니다. 적재 스크립트는 기존 스키마 덮어쓰기를 거절하며, 조회와 계산은 읽기 전용 트랜잭션을 사용합니다. 원본 데이터는 Git에 없으므로 팀 보유본을 별도 전달해야 합니다. 다른 PC에서는 [데이터 확보 안내](docs/role4/DATA_ACCESS.md)와 README의 전처리·적재 절차를 따릅니다.

현재 API 인증은 독립 실행을 위한 서버 토큰 방식이며 기존 앱의 로그인 세션과 호환되는 인증 구현이 아닙니다. 실제 LLM 연결, 기존 화면 연결, 사용자별 권한, 영구 감사 저장 및 외부 배포는 후속 통합 작업입니다.

## 팀 통합 완료 확인

1. 팀 백엔드에서 인증된 사용자의 허용된 선박만 조회되는지 확인합니다.
2. 실제 MRV와 합성 Noon 각각 한 건을 조회하여 출처·단위·null 표시를 확인합니다.
3. 페이지 이동과 `blocked` 계산 결과, 401/403/422/503 처리도 확인합니다.
4. 테스트는 `role4/`에서 실행하고, DB 통합 테스트는 선정 데이터를 적재한 별도 환경을 지정합니다.
